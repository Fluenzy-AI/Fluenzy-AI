All 10 Identified Problems — Code-Level Evidence
🔊 P1 — Multiple AI Voices Speaking Simultaneously
CRITICAL

Location: VoiceAgent.tsx:875–897 | Cause: No turn-ID arbitration on AudioBufferSourceNode scheduling. Multiple turns' audio plays concurrently when user sends activityEnd while AI is speaking.

Fix: Implement AudioPlaybackManager class with exclusive currentTurnId. New turn calls cancelCurrentTurn() first — stops all active nodes, clears Set, resets scheduler. Only chunks matching currentTurnId are scheduled.
🎤 P2 — User Response Lost / Incomplete After Several Turns
CRITICAL

Location: VoiceAgent.tsx:751–823 | Cause (3 layers): ① VAD guard resets vadSpeechActive=false every frame while AI speaks → first 400ms of user speech always missed. ② currentQA.current.answer appends without per-turn reset → multiple turns' answers concatenate silently. ③ No Gemini WS reconnect → mid-session disconnect = answer lost entirely.

Fix: Buffer first 200ms before activityStart. Isolate answer per-turn with turnId. Add Gemini session reconnect with buffer restoration.
💥 P3 — Server Errors / Crash on Interview End
CRITICAL

Location: VoiceAgent.tsx:313–489 | Cause: ① Non-idempotent cleanup — called simultaneously from onerror + onclose. ② onSessionEnd fires at line 330 before saves (triggers unmount while fetches run). ③ Sequential for...await fetch loop aborts on first error → setIsFinished(true) never fires → user stuck.

Fix: Add cleaningUpRef guard (early return if already running). Move onSessionEnd call AFTER all saves. Use Promise.allSettled() for all evaluate-answer fetches.
📡 P4 — VideoAnalysisPanel WebSocket Infinite Reconnect Loop
HIGH

Location: VideoAnalysisPanel.tsx:378–399 | Cause: Stale closure captures isAnalyzing=true at WebSocket creation. After stopCamera() sets it false, the old closure still sees true → reconnect fires → new WS → error → reconnect → ∞.

Fix: Use shouldReconnectRef = useRef(true). Set to false in stopCamera() BEFORE closing WS. Add exponential backoff with max 5 retries.
🔄 P5 — AudioContext Never Closed (Browser Hard-Cap: 6)
HIGH

Location: VoiceAgent.tsx:535–538 | Cause: 2 new AudioContext instances created per session start, never closed in cleanup(). After 6 sessions = 12 open AudioContexts. Browser hard-cap is 6/page → session 7+ fails silently.

Fix: Call audioCtx.close() in cleanup for both contexts. Wrap in try/catch (close() throws on already-closed contexts).
🔑 P6 — Gemini API Key Exposed in Browser Bundle
CRITICAL — Security

Location: VoiceAgent.tsx:534, interviewEngine.ts:81 | Cause: NEXT_PUBLIC_GEMINI_API_KEY is inlined into client-side JS by Next.js. Any user → DevTools → Sources → search "AIza" → finds your key. Used for both Gemini Live sessions AND Prompt 1 reconstruction.

Fix: Move ALL Gemini calls to server-side Next.js API routes. Rename to GEMINI_API_KEY (no NEXT_PUBLIC_ prefix). Client communicates via /api/gemini-proxy WebSocket.
🏠 P7 — FastAPI CORS Wildcard + No WebSocket Authentication
HIGH — Security

Location: backend/main.py:412–418 | Cause: allow_origins=["*"] with allow_credentials=True is a known misconfiguration (Starlette raises runtime warning, browsers reject in strict mode). /ws/behavioral/{session_id} accepts ANY connection — attacker can hijack any session's behavioral data.

Fix: Set specific CORS origins. Add JWT validation on WS handshake: /ws/behavioral/{id}?token={jwt}. Verify against session store on connect.
📦 P8 — No Session Deduplication (Double-Click / React Strict Mode)
HIGH

Location: VoiceAgent.tsx:491 (startSession) | Cause: No mutex on startSession(). React 18 Strict Mode mounts components twice in dev → 2 sessionIds generated. Double-click "Start Interview" → 2 Gemini Live sessions → guaranteed multiple voices at session level.

Fix: Add isSessionStartingRef = useRef(false) guard at top of startSession(). Return immediately if true. Validate uniqueness server-side.
⚡ P9 — ScriptProcessor Deprecated (Main-Thread Audio Blocking)
MEDIUM

Location: VoiceAgent.tsx:721 | Cause: createScriptProcessor(4096, 1, 1) is deprecated in Chrome 113+. Runs on main JS thread, blocking the event loop every 4096 samples (256ms at 16kHz). Causes UI micro-stutter and delays other audio callbacks.

Fix: Replace with AudioWorkletNode. Port VAD + PCM encoding to a dedicated worklet processor running off the main thread.
🔁 P10 — Silence Nudge Uses Stale Session Promise Reference
HIGH

Location: VoiceAgent.tsx:798–816 | Cause: Silence timer sends nudge via sessionPromise.then(s => s.sendText(...)). After session close (sessionRef.current = null), the resolved promise still holds a reference to the dead session object. Calling sendText on a closed session throws an unhandled rejection.

Fix: Check sessionRef.current !== null AND interview state !== ENDING before sending nudge. Use sessionRef.current directly (not stale promise).

AudioPlaybackManager — Single Speaker Guarantee
// The key class missing from the current implementation
class AudioPlaybackManager {
  private currentTurnId: string | null = null;
  private activeNodes = new Set<AudioBufferSourceNode>();
  private nextStart = 0;

  startTurn(turnId: string) {
    if (this.currentTurnId !== turnId) this.cancelCurrentTurn(); // ← cancel old turn first
    this.currentTurnId = turnId;
    this.nextStart = this.ctx.currentTime;
  }

  scheduleChunk(turnId: string, buffer: AudioBuffer) {
    if (turnId !== this.currentTurnId) return; // ← THE key guard: reject stale chunks
    const src = this.ctx.createBufferSource();
    src.buffer = buffer;
    src.connect(this.ctx.destination);
    src.start(Math.max(this.nextStart, this.ctx.currentTime));
    this.nextStart += buffer.duration;
    this.activeNodes.add(src);
    src.onended = () => this.activeNodes.delete(src);
  }

  cancelCurrentTurn() {        // called on barge-in OR new turn start
    this.currentTurnId = null;
    this.activeNodes.forEach(n => { try { n.stop(); } catch {} });
    this.activeNodes.clear();
    this.nextStart = 0;
  }
}
